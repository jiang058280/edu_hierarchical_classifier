# 初高中多学科知识库与题库：AI 批量生成完整提示词

## 目标与适用范围

本提示词用于为当前“教育题目层级分类”项目持续建设两类相互配合、但**不应混淆**的数据资产：

| 资产 | 作用 | 当前项目中的去向 |
| --- | --- | --- |
| RAG 教学知识库 Markdown | 学生问答、教师备课、知识讲解与带引用检索 | 教师端“知识库管理”直接上传 `.md` |
| 正式题库候选题包 | 组卷、练习、作业、错题本、后续人工审核与分类训练素材 | 需经人工审核并录入 `questions` 题库；当前 Markdown 上传**不会自动写入题库** |

生成应分批进行：先用“模式 A”构建可检索的知识讲解和少量典型题，再用“模式 B”按具体缺口批量生成可审核题目。不要让一个超长 Markdown 同时承担所有学段、学科和用途。

## 项目约束

- 学段仅限：`初中`、`高中`；年级使用：初一、初二、初三、高一、高二、高三。
- 学科仅限：数学、语文、英语、物理、化学、生物、历史、地理、政治。
- RAG 上传支持 UTF-8 的 `.md`、`.markdown`、`.txt`、`.docx`、`.pdf`；单文件当前上限为 25 MB。
- RAG 以“学科、学段、年级”进行硬过滤，上传表单的字段应与文件元信息一致。覆盖整个学段时，年级留空。
- Markdown 标题会被识别为章节。`##` 应是一个细粒度知识点；题干、答案、解析、评分点必须相邻，不能把答案统一放在文末。
- 当前模型的粗粒度题型仅为：`选择题`、`判断题`、`解答题`。业务题库可保留更具体题型，但要提供对应的粗粒度标签。
- 当前 RAG 文件上传只建立文档向量索引；它不解析题目字段，也不自动创建正式题库记录。

## 建设规模与批次规则

“每知识点 4 题”只够 RAG 冷启动，不够正式题库。按以下规模安排生成，优先由学科教师审核后再扩大。

| 阶段 | 目的 | 每细粒度知识点建议量 | 产物 |
| --- | --- | ---: | --- |
| P0 | 格式、检索和答案质量验证 | 2～4 道题例 | 1 个模式 A 文件 |
| P1 | RAG 可用覆盖 | 4～8 道题例 + 完整讲解 | 按“学段 × 学科 × 单元”拆分的模式 A 文件 |
| P2 | 基础组卷与练习 | 20～40 道审核通过的题 | 模式 B 候选题包，审核后录题库 |
| P3 | 高频、易错、核心考点 | 40～80 道审核通过的题 | 专题模式 B 候选题包 |

全项目初始可用题库的现实目标为约 **4,000～8,000 道已审核题目**。不要求每个“学科 × 学段 × 年级 × 知识点 × 题型 × 难度”的组合都达到该数量；应依据课程权重、考试频率、错题数据和组卷库存缺口分配。

推荐批次顺序：初中数学/英语/物理/化学 P1 → 其余初中学科 P1 → 高中数学/英语/物理/化学/生物 P1 → 其余高中学科 P1 → 各专题 P2 → 按库存缺口和错题数据生成 P3。

8. 每一道题都是独立可作答单元：题干、选项、答案、解析、评分点和标签必须连续出现，禁止引用“上一题”“上文”“后附答案”。

【模式 A：RAG 教学资料】
仅在“生成模式”为 A-RAG教学资料时执行以下要求。

1. 最终只输出一个完整 UTF-8 Markdown 文档正文；不要输出 JSON、CSV、HTML、代码围栏、创作说明或多余对话。
2. 文档首行是 `# {{文件名去掉扩展名}}`。随后输出“资料元信息”表，字段必须包括：学段、覆盖年级、学科、覆盖范围、批次阶段、版本、生成日期、内容性质（原创教学资料）、适用用途、题目总数。
3. 每个细粒度知识点使用 `## 第 N 单元｜知识点名称`，且按以下固定顺序编写：
   - `### 学习目标`：2～4 条可观察、可评估目标；
   - `### 核心知识`：定义、条件、规律、适用边界、易混点；
   - `### 常见误区`：至少 2 条，写清错误原因；
   - `### 题例`：按“统一题目模板”完整输出本知识点的题；
   - `### 小结`：2～4 条可迁移的方法总结。
4. P0/P1 的单文件正文宜控制在约 8,000～20,000 个中文字符。范围或题量超过此规模时，优先按单元拆分文件；不要压缩成难以检索的超长文档。
5. 文末依次包含 `## 覆盖清单`、`## 自检结果`、`## 待人工复核项`。覆盖清单用表格列出细粒度知识点、一级知识点、题型分布、题数和难度分布；无待复核项时明确写“无”。

【模式 B：正式题库候选题包】

1. 最终只输出一个完整 UTF-8 Markdown 文档正文；不要输出 JSON、CSV、HTML、代码围栏、创作说明或多余对话。
2. 文档首行是 `# {{文件名去掉扩展名}}`。随后输出“候选题包元信息”表，字段必须包括：学段、覆盖年级、学科、单元/专题、批次阶段、版本、生成日期、内容性质（原创待审核题）、题目总数、题型配额、难度配额、导入状态（待人工审核）。

## 人工审核与导入清单

1. 保存为 UTF-8 `.md`，检查文件名、文档元信息、上传表单的学科/学段/年级一致。
2. 模式 A：上传到“知识库管理”后预览分块，发布资料，质量检查通过后激活版本；用基础问法、变式问法、易混问法进行检索调试。
3. 模式 B：由学科教师抽检题干、答案、解析、标签和评分点，去除近重复题；审核通过的题目才进入正式题库。
4. 关注组卷页面返回的“具体库存缺口”，按缺口生成后续 P2/P3 专题，而不是对所有知识点机械等量扩张。
5. 新增题目若将用于模型训练，应另行经过数据去重、标签复核、训练/验证/测试集划分与版本治理；不要直接把 AI 生成候选题混入评测集或覆盖现有训练数据。
