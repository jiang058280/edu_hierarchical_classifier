# 本地 OCR 真实识别验证

## 已完成

复用本机已有 Tesseract.js 7.0.0，新增可选 tesseract_js 后端。原生 Tesseract 后端不变，默认仍 native 且 OCR 关闭。实际 .env、系统 PATH、正式资料和索引均未修改。

从 [Tesseract 官方 tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast/tree/4.1.0) 下载 4.1.0 版 chi_sim、eng 语言包，放在项目 `.ocr_models/tessdata_fast-4.1.0`，已加入 Git 忽略。运行时显式指定本地语言包；缺少资产立即失败，不在识别期间自动联网下载。接口依据 [Tesseract.js 官方 API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)。

## 实测证据

使用项目已有上传 PDF（SHA-256：8969ff894df6c7a66b3102841d48b67f0a9bd00fcdb59a4f40b960c674fad4a2）第 1 页，经 Poppler 渲染后调用真实本地 OCR。

- 用时 6.22 秒，包含单页渲染和 OCR，不包含入库。
- OCR 返回 411 字符；原文字层提取为 397 字符。字符数不同不能换算准确率。
- 报告：`output/ocr_smoke_20260926/report.json`。
- 原页预览及识别文本：同目录 `page-1.png`、`page-1.txt`。
- 可重跑脚本：`scripts/verify_local_ocr.py`；指定源 PDF、模块目录、语言包目录和新的输出目录，拒绝覆盖已有结果。

源 PDF 本身有文字层，本次强制渲染后 OCR 是真实引擎技术冒烟，不是自然扫描件金标测试，也未走正式入库。没有向外部服务发送源文件。

## 原页视觉对照结果

标题和三个章节顺序基本保留，但至少发现以下错误：

| 原页 | OCR |
| --- | --- |
| 01 | Ol |
| 对这些题轻松掌握 | 对这些古轻松掌握 |
| 矩形/正方形 | 抢形/正方形 |

结论：技术链路已实际跑通，但质量未达到无人复核直接使用的标准。尚未计算正式准确率；不能以单页结果代表公式、表格、拍照模糊件或复杂版式效果。

## 部署和后续边界

使用 JS 后端需要配置 EDU_RAG_OCR_BACKEND=tesseract_js、Node 命令、本地 tesseract.js 模块目录和本地语言包目录。运行时目录是本机依赖，不应将个人绝对路径写入共享配置；部署环境需独立提供相应依赖。

下一步应收集允许使用的自然扫描件和人工转写金标，比较渲染分辨率、语言组合与模型版本；再验证混合页、公式和表格。当前继续保留人工审核，不自动开启 OCR 或重建旧知识库。
