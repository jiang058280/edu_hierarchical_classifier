# 原生模型流接入记录

## 已实现

- `streaming.py` 使用异步 HTTP 连接读取聊天 SSE 增量正文；请求 stream=true，不使用整段回答拆字模拟模型流。
- 保留向量/混合检索、重排与证据阈值。引用先由服务端证据构造；本地题库命中、学情统计和证据不足拒答不调用模型。
- 会话先持久化用户问题并发送 session；模型正文逐段发送 token。仅在上游正常 stop 且收到 [DONE] 后保存完整回答，返回 citations 和 done。done 带正式 message_id。
- 拒绝非法 JSON、截断结束、空回答、超长回答及连接提前终止；不将 reasoning 或 reasoning_content 作为答案输出。
- 生成异常或关闭异步生成器会关闭上游资源，记录 stream_incomplete，不保存半截 assistant 内容；取消清理用受保护的审计写入。
- 前端处理 error 和缺失 done，取消读取并释放 reader；只有完成后才显示引用和反馈按钮。
- 默认 `EDU_RAG_NATIVE_STREAM_ENABLED=false`，原分段展示模式保留；未修改本机 .env、未重启或部署服务。

## 协议和验收限制

兼容聊天增量契约为 choices[0].delta.content，要求 finish_reason=stop 及 [DONE]。模型服务需实测支持，不能因“兼容聊天 API”就认定流式行为一致。vLLM 的流式示例将正文和推理字段分开，本适配只消费正文：[官方示例](https://github.com/vllm-project/vllm/blob/main/examples/reasoning/openai_chat_completion_with_reasoning_streaming.py)。

单次网络等待使用既有 rag_request_timeout_seconds；尚非整个请求的总时限。同步检索/数据库操作在线程池执行，取消不能强制终止已经开始的同步调用；没有后台任务恢复、自动重试或断线续传。

原生流会在完整回答落库前显示部分正文。这不是逐句事实审查；引用可定位不等于每句话已验证忠实性，仍需正式人工评测。浏览器中断和数据库故障涉及提交边界：若完整回答已经提交而 done 尚未送达，应通过会话历史查询，不宣称恰好一次交付。

本轮使用受控 HTTP 响应与假模型测试解析、错误、正常完成、会话权限、半截不落库和生成器关闭；前端仅通过 JavaScript 语法检查。尚未完成真实模型流、真实网络断线、浏览器全流程和容量验收，未产生外部模型调用费用。

最终发布检查结果见 `reports/verification/v1_release_latest.json`。
