### 0.3 代码风格与纪律（沿用交接文档第五节全部禁令）

要点重申：页面脚本首行 `const $ = ...`；接口响应读数组加 `|| []` 防御；页面路由只在根路径注册；改表走迁移；**禁止用 PowerShell 内联命令改代码文件**；提交前标准自证；新增数据源登记 `DATA_PROVENANCE.md`。

### 0.4 新项目主线与边界

项目定位升级为 **“基于 RAG 与学情画像的个性化智慧学习平台”**。现有 BERT 多任务分类器继续作为教育元数据引擎，为题目自动补全学科、题型、知识点和学段标签；RAG 负责基于可信教学资料回答问题、解释错题并组织学习内容；学情服务依据真实作答数据计算掌握度；推荐服务据此检索并重排巩固题。

目标闭环：

```text
教师资料/题库 → 分类标注 → 知识库审核发布 → 学生作业/问答
       ↑                                           ↓
教师复核 ← 质量反馈 ← 个性化巩固题 ← 学情画像 ← 作答记录
```

边界约束：

1. 产品中使用“学情画像/学习画像”，不进行性格、智力、家庭背景等人物推断；
2. 学情结论必须由结构化作答数据计算，LLM 只负责解释，不作为掌握度的唯一裁决者；
3. 姓名、账号和原始作答记录保留在 MySQL，不写入 Milvus；
4. 学生侧只能检索已发布资料，回答必须带来源；证据不足时明确拒答；
5. 当前 `edu_question_dedup` 继续只服务查重，RAG 使用独立 collection 和专用 Embedding 模型；
6. 架构参考 `D:\knowforge-rag-platform`，复用其分层思想与成熟机制，但首期不引入多租户、GraphRAG、独立意图 BERT 和复杂多级缓存。

## RAG 主线总览（M2 后执行）

M2 是 RAG 个性化能力的前置数据闭环。M2 完成后，原 M3“学情与练习”升级为三段式路线：先建立可治理的教育知识库，再完成带引用的 RAG 问答，最后把作答数据、画像和题目检索串成个性化巩固闭环。

从 KnowForge 复用的核心模式：

| KnowForge 机制 | 本项目落点 |
| --- | --- |
| `QAService → pipeline → retrieval/LLM` 分层 | 新建 `EducationQAService`，API 层只做鉴权、校验和流事件转发 |
| FAQ + 文档双路检索 | 标准知识问答快速直出；教材/讲义进入文档 RAG |
| BGE-M3 + CrossEncoder Reranker | 中文稠密召回与候选重排，不复用分类 BERT 的 CLS 作为 RAG 主向量 |
| 查询改写与查询变体 | 将“这题为什么错”等追问补全为包含题目、知识点和会话上下文的查询 |
| 知识库版本状态机 | `STAGED → ACTIVE → ARCHIVED`，支持激活、回滚和增量入库 |
| 文件指纹与引用式增量 | 未变化资料复用原 chunk，变更资料才重新切分和向量化 |
| 引用校验与证据置信度 | 答案显示资料名、章节、页码/题号；低证据问题拒答 |
| 检索调试、反馈、Trace、质量门禁 | 教师可解释检索结果，Bad Case 可复核，固定评测集阻断劣化版本 |

目标检索域：

- `edu_rag_documents`：教材、教师讲义、知识点说明、公式和解题方法；
- `edu_rag_questions`：题干、答案、解析、知识点、题型和难度；
- `edu_rag_faq`：教师审核后的标准问答，高置信命中可直接返回；
- `edu_question_dedup`：保持现状，仅用于录题查重。

## 结语

本计划把后续建设重排为“作业数据闭环 → 教育知识库 → RAG 问答 → 学情画像与个性化巩固 → 联合治理”。执行原则不变：**每阶段可演示、每任务可验收、每决策留痕、每一步可回滚**。完成 M2 后平台具备真实学习数据入口；完成 R2 后具备可展示的可信教育 RAG；完成 R3 后形成“诊断—讲解—练习—再诊断”的数据飞轮；M4 收口后达到可私有化交付的完整形态。
