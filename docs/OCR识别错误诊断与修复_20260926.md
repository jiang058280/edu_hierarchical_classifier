# OCR 识别错误诊断与修复

## 结论

错误发生在 OCR 识别阶段，而非 MySQL 编码或向量化阶段。使用同一原始扫描 PDF，独立调用本地识别即可复现标题乱码、表格漏字和符号混淆；服务端保存的文本与 OCR 输出对应。

本轮修复了这份样本的标题/章节识别以及表格数值漏识别，数学符号仍有残余歧义，未宣称完整质量通过。

## 原因与证据

1. 整页自动分区（PSM 3）没有专门进行表格分析。切换 PSM 6/11 仍不能可靠恢复表格；按检测出的横竖线逐单元格识别后，两行数值恢复。
2. 轻量 fast 模型和中英文联合识别对标题、中文夹杂公式存在误识别。逐行裁剪与完整整数模型组合明显改善了这份样本，但并不意味着适合所有文档。
3. 原样本按 200 DPI 制成图像，再渲染到最长边 3000 像素引入重采样。对照原栅格尺寸与 3000 像素结果，部分文字在后者更差；本次测试最长边设为 2339，与原页尺寸相符。这是样本参数，不建议作为所有 PDF 的通用最优值。
4. 通用文本 OCR 会混淆 `<` 与 `〈`、`×` 与 `X`、`x` 与 `X`，单纯加强中文模型不能保证数学语义正确。没有依据参考答案自动改字或补表格。

官方资料也说明 [Tesseract 表格识别需要额外版面分析](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)，不同模型存在速度与精度权衡，见 [官方模型说明](https://tesseract-ocr.github.io/tessdoc/Data-Files.html)。

## 实施的修复

- 增加可选 `EDU_RAG_OCR_LAYOUT_MODE=lines_tables`，原 page 模式和默认关闭状态保留。
- 用图像像素投影检测行及简单有框表格，不使用此页固定坐标；文本按行识别，表格按单元格识别并按行输出分隔符。
- 识别裁剪区域加白边；只清理相邻中文之间的多余空格，不推断或替换数学内容。
- 明确拒绝过多行、表格或单元格，仍受单页子进程超时限制。
- 适用范围是正向横排单栏和简单完整框线表格，不承诺多栏、倾斜、合并单元格、无框表格。sharp 和本地语言包是 JS 模式的部署依赖。
- 使用官方 tessdata 4.1.0 完整整数模型进行真实重建。tessdata_best 浮点模型在当前 WASM 引擎报缺少 DotProductSSE，旧 best_int 包有语言加载异常，均未用于最终重建。
