# RAG 评测链路修正

## 本次修正

原脚本先调用 retrieval.debug，再调用 answer；后者内部还会检索。这样一次用例会发生两次检索，报告中的候选与生成时实际证据可能不一致，耗时也包含重复检索。

现在由回答服务通过可选的 evaluation_trace 输出本次实际执行路径。评测只调用一次 answer，不改变正常接口响应，不额外检索，也不绕过权限与证据阈值。

- RAG 路径记录真实候选、来源及回答，召回指标使用这一批候选。
- 本地题库路径不调用 RAG 检索，单独累计 local_question_count，不进入资料分块召回率分母。
- 本地题库来源来自服务端构造的标准题引用，避免误判为不存在于 RAG 候选中的错误引用。
- 报告保留 answer、reason、route，便于人工审核。正文可能包含业务资料，应按内部数据管理，不自动上传。
- latency_ms 从调用回答服务前计时，覆盖本地路由、实际检索和生成；不是包含 HTTP、排队、SSE 或浏览器渲染的端到端延迟。

## 多轮场景的限制

当前脚本仍是单轮评测，不实现会话回放。任何 ready=true 用例如果属于 follow_up，或携带非空 conversation_history，正式执行会在连接数据库或调用模型之前停止，输出 unsupported 和具体用例列表，退出码为 2。

--dry-run 仍只校验，不调用服务；它会列出 execution_errors，不代表所列用例可以执行。未审核草稿仍保持 not_ready，未改成 ready=true。

这意味着含已审核连续追问的完整验收集不能直接用本脚本完成验收，需补齐独立会话回放工具后再运行；不会偷偷跳过多轮用例，也不会把上一轮历史简单拼进问题冒充线上链路。

## 验证与剩余事项

新增测试覆盖单次检索、本地路由统计、多轮拒绝和 CLI 全量前置检查。测试使用受控替身，不代表真实模型效果。

仍需人工确认源资料、答案和活动版本分块关联；引用来源一致性只是代理指标，不是答案事实正确率。正式质量对比、真实模型延迟以及多轮回放仍待验收。
