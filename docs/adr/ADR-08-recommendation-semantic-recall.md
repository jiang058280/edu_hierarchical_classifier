# ADR-08：推荐语义召回（错题种子 + 查重向量集合 + 加成打分）

日期：2026-09-27 ｜ 状态：Accepted（已实现并验证）

## 背景

R3.3 推荐为纯规则召回：候选池为学段内全部已发布题，按薄弱度/同知识点/难度/新颖度打分。两个已知局限：
1. "同知识点"项依赖模型预标注的 50 个粗类标签，标签不同但语义相近的题拿不到"同知识点"分；
2. 题库 1327 题实际带有 354 个教师细粒度标签，规则匹配无法表达"细类不同、语义相近"。

同时发现：`edu_question_dedup` 向量集合自建库以来始终为空（0 向量）——题目 CRUD 与批量导入路径均未写入向量，查重与"举一反三"类功能长期空转。

## 决策

1. **向量源**：复用 `edu_question_dedup`（BERT [CLS] 768 维，COSINE）。备选的"资料分块桥接"绕远路、"text-embedding-v4 重嵌题库"质量更好但给录题链路加新外部依赖——列为二期升级项，切换单点在 `SemanticRecaller`，融合逻辑不变。
2. **融合方式**：候选池本身已是学段内全部题目，语义不做"新增召回通道"，而是**打分项**——`score = min(1.0, base + 0.12 × 归一化带内相似度)`，推荐理由追加"与错题语义相关 N%"。原"40% 配额"设计随通道方案的取消而取消，加成权重天然封顶其影响。
3. **相似度卡带**：`[0.55, 0.95)`——达到 0.95（查重阈值）视为近似重复题排除，低于 0.55 视为噪声不计分。实测分布（初三角题种子）全部落在 0.73-0.89，卡带无需调整。
4. **种子**：学生错题本前 3 条的题干主体（剥离粘贴序号、截断 200 字）；错题本身经 exclude 排除，不会被推荐回来。
5. **降级**：Milvus 不可用时 `search_similar` 返回空、加成为零、推荐退化为纯规则（查重模块既有降级语义）。
6. **工程配套**：
   - `scripts/backfill_question_vectors.py` 一次性回填 1327 题向量（28 秒）；
   - 题目创建/批量创建/内容编辑路径同步 `dedup.upsert_question`（Milvus 不可用静默跳过），查重功能自此对新题生效；
   - 配置 `EDU_RECOMMEND_SEMANTIC_ENABLED`（默认关闭）+ 种子数/top-k/卡带/权重五参数。

## 后果

- 正向：跨知识点语义相近题可进入推荐前排；查重功能被修复；推荐理由保持可解释；质量指标（知识点匹配率/重复率）持续可观测。
- 代价：推荐排序引入向量检索依赖（Milvus 故障时行为同旧版）；BERT embedding 的语义区分度弱于专用检索模型，若二期实测采纳率不足则换 text-embedding-v4 重嵌。
- 已验证：单元测试 7 项；真实数据端到端（初三错题种子 → Top10 中 7 条带语义理由，知识点匹配率 1.0、零重复）。
