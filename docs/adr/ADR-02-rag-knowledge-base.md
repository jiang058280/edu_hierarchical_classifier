# ADR-02：教育知识库的版本、权限与索引契约

| 项 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-09-09 |
| 范围 | R1 教育知识库底座 |
| 关联计划 | `docs/剩余工作总计划.md` R1.1～R1.6 |

## 背景

平台已有题库、班级和作答记录，但尚不能把教师审核过的教材、讲义和知识说明转为可追溯的资料库。RAG 后续必须做到：学生只能查到已发布且与自己学段匹配的资料；每条回答可回到原始资料；资料更新或撤回不会破坏历史版本和审计。

## 决策

### 1. 唯一事实源与版本状态机

MySQL 是资料、分块、入库任务和知识库版本的唯一事实源；Milvus 只保存向量及检索所需最小元数据，任何向量都不能单独成为业务事实。

知识库版本状态只能是：

```text
STAGED  --质量检查通过-->  ACTIVE
ACTIVE  --激活新版本-->    ARCHIVED
ARCHIVED --回滚-->          ACTIVE
```

任一时刻只有一个 ACTIVE 版本。创建、激活、回滚、下架和重建都必须写 `audit_logs`。未完成或失败的资料只停留在 STAGED，不可被学生检索。

### 2. 文档、分块与索引契约

首期资料类型：PDF、DOCX、Markdown、TXT。每次导入都创建可追溯的文档记录，按文件 SHA-256 识别完全相同文件；相同内容可复用已有分块，变更文件生成新有效期窗口，旧版本保留用于回滚。

父块约 1000 个中文字符，用于来源预览；子块约 350 个字符，用于向量检索。优先按标题、段落和页码切分，绝不在单个字符或 UTF-8 字节中截断。

每个可检索子块必须携带以下 metadata：

| 字段 | 含义 |
| --- | --- |
| `document_id` / `parent_chunk_id` | 原始资料及父块归属 |
| `subject` / `grade_band` / `grade` | 学科与学段硬过滤依据 |
| `knowledge_node_id` / `chapter` | 知识点与章节定位 |
| `source_name` / `page_number` | 向用户展示的可核验来源 |
| `kb_version` / `status` | 知识库版本与可检索状态 |
| `allowed_roles` | 默认 `student,teacher,admin`，后续可收紧 |
| `content_hash` | 分块复用与完整性校验 |

题库检索使用独立的 `edu_rag_questions` collection；教师资料使用 `edu_rag_documents`；标准 FAQ 使用 `edu_rag_faq`。既有 `edu_question_dedup` 只做录题查重，不与 RAG 混用。

### 3. 权限与未成年人数据边界

教师只能管理自己创建的资料、任务和草稿版本；管理员可以治理全局版本。学生只可读取 ACTIVE 版本中 `published` 的资料，检索时强制应用学段、年级、角色和发布状态过滤。

姓名、账号、班级名、原始作答、提交记录和画像明细不得写入 Milvus 或发送给模型 Provider。后续 RAG 上下文只传最小化、匿名化的学习事实，并以服务器端权限校验为准，前端不传信任边界字段。

### 4. Provider 与可用性

Embedding、Reranker 和 LLM 都经独立适配器调用 OpenAI-compatible 接口；模型、地址、密钥、超时、top-k 和阈值均来自 `EDU_RAG_*` 配置。业务层不得直接依赖某家模型厂商。

R1 入库失败不得影响题库、作业、判分或登录。Milvus/Embedding 不可用时，任务记录失败原因，版本不允许激活；R2 问答必须明确返回“资料不足或知识库暂不可用”，不得自由编造答案。

### 5. 质量门槛与回滚

激活前至少检查：文件处理成功、非空分块数大于零、空内容比例可接受、所有子块具备 `content_hash` 与必要来源字段、向量数量与数据库可检索子块数量一致。检查结果写入版本统计。

激活在单个数据库事务中切换指针；索引写入先于指针切换。任何写入失败不切换 ACTIVE 指针。回滚只切换到历史 ARCHIVED 版本，并重新验证其索引可用性；无可用索引时拒绝回滚。

## 备选方案及否决原因

| 方案 | 不采用原因 |
| --- | --- |
| 只在 Milvus 保存资料和版本 | 无法可靠审计、回滚和治理，且难以处理权限 |
| 直接让学生上传并立即可检索 | 无法保证资料来源、学段和内容安全 |
| 复用题目查重 collection | 向量模型、metadata、生命周期和访问边界不同 |
| 资料上传后立即调用 LLM 摘要 | 增加外部数据暴露；R1 先完成可控入库，摘要留待后续需求 |

## 验收约束

- 同一文件重复导入不增加重复向量；
- 修改、下架和回滚均能在 MySQL 版本记录中还原；
- 任一学生请求都无法跨学段或读取 STAGED/ARCHIVED 内容；
- 向量服务故障时不改变作业主链路，且 ACTIVE 指针不被错误切换。
