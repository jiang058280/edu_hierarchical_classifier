# 会话主题记忆接入

## 完成的代码

默认关闭的 `EDU_RAG_CONVERSATION_MEMORY_ENABLED=false` 已写入配置示例，实际 .env 未改动。

开启后，同步与原生流会话路径在写入本轮问题前，读取当前学生自己的会话历史。数据库只取最近 8 条，每条正文最多 400 字；最终最多使用 3 个已完成、未拒答轮次的用户问题。不会把旧助手回答、引用、姓名或完整学生档案传给生成模型作为记忆。

有限规则识别“刚才、上述、上一题、继续、那……呢”等显式追问，把历史主题与当前问题合并用于本轮检索，合并长度不超过 2000 字。明确换话题、未识别为追问、长度不足以加入历史时，保持原问题。

被补全的追问不走本地题库直接答复，避免重复返回上一题标准答案；重新执行当前权限与活动知识版本下的 RAG 检索、阈值判断和服务器引用。没有当前证据仍拒答，不把历史回答当备用证据。

## 边界与验证

- 所有权检查先于历史读取；SQL 还限定本人及 student 会话。
- 历史末尾有未完成问题、连续用户消息等歧义序列时，不猜测配对。清空会话后记忆随之消失。
- 这只是用户问题主题记忆，不是完整对话摘要或模型级指代消解。依赖上一轮答案中某个具体步骤的追问，可能仍需用户补充。
- 有限规则会漏判或误判，截断可能丢失细节，多主题会话也可能干扰召回；需真实回放评估后决定是否开启。
- 历史文字被标为非证据，但提示词声明不等于彻底消除提示注入风险。当前权限检查、资料证据与拒答边界仍是必要条件。
- 尚未实现同会话并发请求串行化、请求与回答的显式配对 ID，不能保证并发写入时完整还原轮次。建议测试时串行提问。
- 同步与原生流共用补全逻辑；原生流断线仍沿用原有不保存半截回答机制。

测试覆盖历史预算、拒答/未完成轮次、越权访问、独立新问题、同步/流式传参、重新检索及无证据拒答，另有独立测试库校验历史查询限长与清空行为。本轮未启用本机开关、未调用真实模型、未修改人工审核草稿。

## 验收步骤

1. 在隔离环境使用测试账号与审核后的资料开启开关。

3. 检查承接主题、换话题、证据不足、资料下架、会话清空和中断后重试。
4. 人工审核引用支持程度及答案正确性，不能用“接口完成”替代效果验收。
