# 本地 PDF OCR 接入

后续更新：已新增可选 Tesseract.js 本地后端并复用本机运行时完成真实单页 OCR 冒烟；存在识别错误，仍未通过质量验收。详见 `docs/OCR真实识别验证_20260926.md`。下方原生 Tesseract 缺失的记录保留作为当时环境状态。

## 流程

默认关闭 `EDU_RAG_OCR_ENABLED`，实际 .env 未修改。开启后，PDF 先用 pypdf 提取逐页文字；非空白字符少于默认 20 个的页面，再用 Poppler pdftoppm 渲染为 PNG，交给本地 Tesseract 识别。识别文本替换该页文字层，按原页序进入清理、父子分块与入库流程。任务 metrics 记录 ocr_pages（从 1 开始）。

原始 PDF 与页面图像不发送到外部 OCR 服务。注意后续 Embedding 入库仍沿用项目配置的模型服务，OCR 本地化不代表整个入库链路离线。

## 依赖与配置

需要安装 Poppler、Tesseract 及 chi_sim/eng 语言包。可执行文件由 PATH 查找，或设置配置示例中的 EDU_RAG_OCR_PDFTOPPM_COMMAND、EDU_RAG_OCR_TESSERACT_COMMAND 为绝对可执行路径，不是任意 Shell 命令。不会自动下载或安装系统工具。

- EDU_RAG_OCR_LANGUAGES 默认 chi_sim+eng。
- EDU_RAG_OCR_MIN_TEXT_CHARS 默认 20，属启发式阈值，需按资料调整。
- EDU_RAG_OCR_MAX_PAGES 默认每文件最多 20 个待识别页，超限直接失败。
- EDU_RAG_OCR_MAX_SIDE_PIXELS 默认最长边 3000 像素，避免无限制放大。
- EDU_RAG_OCR_TIMEOUT_SECONDS 默认每次子进程 60 秒，渲染与识别分别计时，不是整个入库总时限。

工具以参数数组启动、不经过 Shell，Windows 不弹交互窗口。中间文件放入独立临时目录，正常完成或可处理异常后清理；进程强杀或系统崩溃仍可能留下临时文件。

缺少依赖、超时、子进程失败或空识别文本会进入入库失败路径，不将部分成功页当作完整文档。空白页面也会触发失败，需要人工确认或预处理，这是当前保守策略。

## 验证与限制

专项测试 23 项通过，覆盖混合 PDF 页序、稀疏页选择、关闭开关、失败传播、页数限制、依赖缺失、参数数组、超时及临时目录清理。测试使用可控替身，不代表真实 OCR 准确率。

本机发现 pdftoppm，未发现 Tesseract，尚未进行真实扫描件的识别与视觉对照。按 PDF 技能要求，后续须将真实样本页面渲染出来，对照原页逐项检查识别结果，尤其是公式、表格、上下标和多栏阅读顺序。

当前未实现公式专用识别、复杂版面恢复、旋转纠偏、OCR 置信度门禁、分块精确页码映射。文字层很多但同时含扫描图片的混合页可能被启发式规则漏掉；文字乱码也不能仅靠字符数可靠识别。不能据此宣称所有 PDF 内容都可无损解析。

原生解析仍在入库进程中运行；像素/页数和子进程超时限制不是完整的恶意 PDF 沙箱。生产应配置进程隔离、系统资源限额及队列容量。
