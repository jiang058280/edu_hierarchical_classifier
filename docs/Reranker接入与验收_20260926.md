# 独立 Reranker 接入与验收

## 本轮实现

新增 `edu_core/rag/reranking.py`，通过显式配置的 cohere_compatible 协议调用 POST {base_url}/rerank。输入 query、documents、model、top_n；返回 results 中的 index 和 relevance_score。接口契约参考 [Cohere Rerank 官方文档](https://docs.cohere.com/v2/reference/rerank)，不声称这是 OpenAI 标准接口，也不自动使用任何云供应商。

检索流程：两路召回 → 授权过滤 → RRF → 限制重排候选数 → 模型打分 → 再次校验授权与正文一致性 → 返回 Top-K → 独立证据阈值 → 生成。向量单路也可单独启用重排。

默认仍为 disabled，不改本机 .env、不重启服务、不下载模型、不发送真实资料至外部服务。

## 分数与失败边界

- score_kind 标明 vector 或 reranker；保留 vector_score、bm25_score、rrf_score 与 reranker_score 供定位。
- 启用后必须显式填写 EDU_RAG_RERANKER_MIN_SCORE（0～1，经代表性资料评测确定），不默认复用向量阈值。
- BM25-only 候选经过真实重排打分后可进入证据判断；未重排时仍采用原先保守处理。
- 校验全部候选均有唯一且合法的输入索引；拒绝缺失、重复、越界、布尔索引以及非数值、非有限值、越界分数。
- HTTP 错误、超时、非法响应直接失败，不静默降级生成；错误不带 URL、密钥或响应正文。当前没有自动重试，避免额外费用和放大故障。
- 默认最多重排 24 条，可配置 1～100。仅发送问题和授权片段正文，不发送学生身份或全部历史。

## 启用前需要

1. 明确部署协议和模型；base_url 填 /rerank 之前的前缀，不能误填聊天端点。无认证私有服务允许不填 API key。
2. 核对资料是否允许发送至该部署；本轮未进行真实网络模型调用。
3. 用已审核评测集标定独立阈值，比较 Recall、MRR、答复质量、拒答与新增延迟。
4. 若服务输出原始 logits 而非 0～1 分数，先建立独立适配，不直接启用本契约。
5. 验证请求大小、模型文档截断、超时及并发限制，再开启配置。接口可调用不等于质量已达标。

## 验收状态

Mock 协议与集成单测已验证请求结构、索引映射、错误响应、权限复查及独立阈值。最终全量结果见 reports/verification/v1_release_latest.json。真实模型联调和正式质量评测尚未完成。
