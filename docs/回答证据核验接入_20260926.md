# 回答证据核验接入与验证

## 已实现的行为

新增 `EDU_RAG_GROUNDING_CHECK_ENABLED` 配置。启用后，文档 RAG 先生成草稿，再让核验调用检查每项定义、事实、计算和引用是否被本轮实际提供的资料支持。核验只拿到本轮问题、实际截断后的证据和候选回答；不使用未送入上下文的原始全集充当依据。

核验返回严格 JSON 布尔结果及具体问题。回答包含不存在的 `[数字]` 或 `[资料数字]` 引用时，程序直接判为不通过。发现不支持内容后最多重写一次，重写结果必须重新核验；再次失败、核验结果格式错误、核验服务不可用时均拒答，不返回未验证的草稿或引用。

一般回答消耗 2 次模型调用（生成、核验）；重写路径最多 4 次。核验复用已配置的回答模型，所以它是概率性检查，可能误判，不能保证消除幻觉，也不是独立模型或人工审核。

流式接口启用此配置时会先收齐模型输出并完成核验，然后发送最终文本；草稿不会提前进入页面。代价是失去逐字即时显示，首段等待包含生成和核验时间。未开启此配置的流式行为保持原样。题库标准答案直出及检索无证据拒答不额外调用核验模型。

会话日志将核验拒答记为 `failure_stage=grounding`，区分检索证据不足的 `evidence`。同时修复了聊天 Provider 在 HTTP 错误分支调用不存在方法的问题，服务端错误现在按受控 Provider 异常处理。

## 真实资料验证

仍使用校对资料 24、测试版本 3，通过进程内只读作用域验证。真实 MySQL、Milvus、Embedding、回答及核验模型均参与；正式激活版本保持 1。该验证专门覆盖文档 RAG，没有执行学生 HTTP 会话端到端流程。

首轮报告 `output/ocr_corrected_publication/answer_grounding_verification.json`：

- 增减性题生成了资料外的“斜率”定义，核验拦截后触发重写，再次核验通过。最终回答仅用 k < 0 的原资料规则。
- 核验器也曾将一些有依据的表达列入问题，体现误判风险；计算题仍有泛化表述。因此进一步将生成风格从“先讲概念”改为直接解题。

最终报告 `output/ocr_corrected_publication/answer_grounding_final.json`：

| 用例 | 最终结果 | 模型调用 | 单次耗时 |
| --- | --- | --- | --- |
| y = 2x + 1，x = 2 | 回答 2 × 2 + 1 = 5，例题引用正确 | 2 | 5.99 秒 |
| y = -2x + 4 的增减性 | 依据 k = -2 < 0 回答减小，没有补充斜率定义 | 2 | 5.00 秒 |
| 高中高三范围问该题 | 无证据拒答、无引用 | 0 | 0.60 秒 |

已人工阅读（助手复查）最终两条回答及对应证据。本轮修复了现有样本暴露的问题，不将三例冒烟作为正式准确率、忠实度或 P95 验收报告。
